# OPD Algorithm: On-Policy Distillation

## Overview

**On-Policy Distillation (OPD)** is a knowledge distillation technique for large language model post-training. In OPD, the **student model** generates responses (on-policy rollout) and a frozen **teacher model** scores them. The student learns to match the teacher's output distribution by minimizing the KL divergence between the student and teacher log-probabilities on the student-generated response tokens.

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│   Prompts    │ ──► │  Student Model   │ ──► │   Rollout:       │
│              │     │  (trainable)     │     │   n_samples per  │
│              │     │                  │     │   prompt         │
└──────────────┘     └──────────────────┘     └────────┬─────────┘
                                                        │
                                                        ▼
                                              ┌──────────────────┐
                                              │  Teacher Model   │
                                              │  (frozen)        │
                                              │  scores tokens   │
                                              └────────┬─────────┘
                                                        │
                                                        ▼
                                              ┌──────────────────┐
                                              │  KL Loss:        │
                                              │  KL(student||    │
                                              │    teacher)      │
                                              └────────┬─────────┘
                                                        │
                                                        ▼
                                              ┌──────────────────┐
                                              │  Student Update  │
                                              │  (gradient step) │
                                              └──────────────────┘
```

## Mathematical Formulation

For each response token `a` generated by the student policy `π_s`:

- **Student log-probability**: `log π_s(a | context)`
- **Teacher log-probability**: `log π_t(a | context)`

The distillation loss is the KL divergence from the student to the teacher distribution:

```
Loss = KL(π_s || π_t) = E_{a ~ π_s}[log π_s(a) - log π_t(a)]
                    ≈ mean(log π_s(a) - log π_t(a))   # over response tokens
```

The teacher log-probabilities are detached from the computation graph (the teacher is frozen), so the gradient flows only through the student:

```
∇Loss ≈ mean(∇log π_s(a))
```

This pushes the student's log-probabilities toward the teacher's on the tokens the student itself generates.

### Temperature Scaling

A temperature parameter `τ` softens both distributions before computing the KL:

```
Loss = mean(log π_s(a)/τ - log π_t(a)/τ) * τ²  (approximate)
```

In this implementation, applying temperature to both logprobs scales the loss linearly:

```
Loss_τ = mean((log π_s(a) - log π_t(a)) / τ) = Loss / τ
```

## Key Features

| Feature | Description |
|---------|-------------|
| **On-policy** | The student learns from its own generated responses, not a static dataset |
| **No reward model** | Unlike PPO/GRPO, OPD doesn't need a reward model or advantage computation |
| **No critic** | No value function, no GAE — just teacher-student KL divergence |
| **Frozen teacher** | The teacher model is never updated, only used for scoring |
| **Temperature control** | Configurable temperature for softening distributions |

## Configuration

### OPDTrainerConfig

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `ref_ckpt` | `str \| None` | `None` | Teacher model checkpoint path (defaults to student checkpoint) |
| `opd_kl_coef` | `float` | `1.0` | Coefficient scaling the KL loss |
| `opd_temperature` | `float` | `1.0` | Temperature for softening log-probabilities |

Inherited from `RolloutTrainerConfig`:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `n_samples` | `int` | `8` | Number of completions to sample per prompt |
| `temperature` | `float` | `1.0` | Sampling temperature for rollout |
| `top_p` | `float` | `1.0` | Top-p (nucleus) sampling parameter |
| `top_k` | `int` | `-1` | Top-k sampling parameter (-1 = disabled) |

## Usage

### Basic Training Script

```python
import areno.api
from areno.api.trainer_config import OPDTrainerConfig
from areno.api.trainer_factory import build_trainer

# Configure OPD training
config = OPDTrainerConfig(
    algo="opd",
    ckpt="/path/to/student/model",
    dataset_path="/path/to/training/data",
    ref_ckpt="/path/to/teacher/model",  # stronger teacher model
    opd_kl_coef=1.0,
    opd_temperature=1.0,
    n_samples=8,
    batch_size=32,
    epochs=3,
)

# Build the trainer
trainer = build_trainer(
    config,
    instance=areno.api.Trainer(...),
    dataset=dataset,
    reward_fn=None,  # OPD doesn't need a reward function
    loss_fn=areno.api.loss_fns.opd_loss_fn,
)

# Run training
trainer.fit()
```

### CLI Usage

```bash
python -m areno train \
    --algo opd \
    --ckpt /path/to/student/model \
    --dataset /path/to/data \
    --ref-ckpt /path/to/teacher/model \
    --opd-kl-coef 1.0 \
    --opd-temperature 1.0 \
    --n-samples 8 \
    --batch-size 32
```

## Algorithm Registration

The OPD algorithm is registered in `areno/api/algorithms.py` as a built-in algorithm:

```python
AlgorithmSpec(
    name="opd",
    trainer_cls=_load_opd_trainer,
    default_loss_fn=opd_loss_fn,
    requires_rollout=True,
    loss_fn_factory=_bind_opd_loss,
)
```

This means:
- The algorithm name is `"opd"`
- The trainer is `OPDTrainer` (lazy-loaded)
- The default loss function is `opd_loss_fn`
- Rollout is required (on-policy algorithm)
- The loss factory binds `opd_kl_coef` and `opd_temperature` from config

## Comparison with Other Algorithms

| Aspect | OPD | PPO | GRPO | DPO |
|--------|-----|-----|------|-----|
| **Type** | Distillation | RL | RL | Preference |
| **On-policy** | Yes | Yes | Yes | No (offline) |
| **Reward model** | No | Yes | No (group norm) | No |
| **Critic** | No | Yes | No | No |
| **Reference model** | Teacher (scoring) | KL penalty | No | Reference policy |
| **Loss function** | KL(student \|\| teacher) | Clipped actor + KL | Clipped policy gradient | Preference margin |
| **Learning signal** | Teacher logprobs | Reward + GAE | Group-relative rewards | Preference pairs |
